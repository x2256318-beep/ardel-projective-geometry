# 規則の追加の案：内部照合（CLAUDE.md への条文化は著者が行う）

2026-11-14。著者の判断「足す」（Part 257 の着手前の文書 §10）を受けた条文の案です。CLAUDE.md は変えていません。

## 案 1：着手前の 4 点に 5 点目を足す

> 5. **鎖の中の照合（内部照合）**：問いと、予定している主な文について、自分の鎖（xlsx の「定理と証明」と、Lean の全宣言）を検索し、同じ文・より強い文・直ちに出る文がないかを調べる。見つかったら、その定理を使う計画にし、示し直さない。見つからなかった場合も、検索した語と範囲を書く。

## 案 2：パートを閉じる条件に足す

> 各主要結果について、［既知／再導出／新規候補］のラベルとは別に、内部照合の結果［鎖にある（Part n の宣言名）／鎖にない］を記録する。鎖にあるものは、Lean の docstring にその宣言名を書く。内部照合は次の 3 段で行う。
> 1. 機械的な候補選び：型に現れる定数（プロジェクトの定義は値の定数まで展開）の近さで、前の宣言から候補を選ぶ。
> 2. Lean での確認：候補の組ごとに、一方を他方にそのまま当てて（`exact`・`apply` と仮定）通るかを、鎖の外のファイルで確かめる。定義は `HEq` の `rfl` で確かめる。
> 3. 独立の照合：新しいセッションに、対象と候補の形式文の全文を渡し、判定させる（Read と Grep だけ）。

## 案 3：兆候 1 の補足

> 自前の名前は、外の文献だけでなく、自分の鎖の名前とも照合する。例：Part 256 の `prodChar` は、Part 195 の `cmul`、Part 232 の `charMul` と同じ定義だった。

## 限界（条文に添える注意）

- 機械的な候補選びは、上位 k 個に入らないものを見落とします。照合者の Grep で補います。
- 直接の当てはめは「同じ文」と「代入で出る文」しか確かめられません。数行の系（C）は照合者の判定です。
